# NoaCopilot 的 Flat320 推理环境

从 Windows 发布包顶层的 `MiaCode.exe` 启动，在 NoaCopilot 设置中选择谱面 checkpoint。v19 使用逐拍编辑协议。在 `app/noa-copilot/checkpoints` 中放入权重，或在设置中选择外部文件。启用后，应用启动时加载选定权重。v18.4、v18.5 权重仍可使用随包提供的历史解码器。

## 在编辑器里使用

- 编辑器默认用空格播放或暂停谱面预览。在当前行的 `||` 后可正常输入空格。“设置 → 编辑器”中的“编辑器中点按空格是否播放谱面”可以关闭。
- 普通编辑可随时停笔，按 Tab 时才发起光标续写。光标在长条、星星路径或多押内部时，从同拍前一个已保留音符组之后的可用位置开始，重新采样当前整个 Moment 的起音和内容。NoaCopilot 设置中的“续写行数”和“每行拍数”默认均为 4。当前行已写 2 拍时，补 2 拍后再写 3 个完整行。当前行已满或超过 4 拍时，从下一行开始写满 4 行。续写到音频末尾即止。
- 在含骨架的连续行中，Tab 填充该块，选中部分占位符则只填所选部分。普通拖选后可点击“填充采音”，Alt 拖选松手后直接填充。
- `x` 生成一个非 Slide 音符，`*` 生成单分支 Slide，`x**` 生成双分支 Slide。`1h[4:1]/x` 保留左边的 Hold。草稿占位符在时间轴上显示为 1 号 tap，播放时可听到 key 音。
- 同一推理进程默认预计算 3 条候选，高级设置可改为 1–8 条。↓ 向后翻页时继续预取。当前候选尚在生成时，↓ 会在光标旁提示稍等。当前候选完成后，↓ 可以接看下一条的实时输出，已算完的候选会直接显示。↑ 回看上一条候选。↑、↓ 会将播放位置带回当前续写起点。在第一条候选上再按 ↑ 会回到原谱并退出续写，随后方向键移动编辑器光标。候选穷尽时光标旁会短暂提示。
- 编辑器内按 → 采纳一拍，时间轴移到新起点并补充候选，Esc 保留已采纳的拍。点击时间轴或预览播放按钮后，↑、↓ 仍可切换候选，Tab 仍采纳整个当前候选。时间轴上的 → 继续移动播放位置。单击、框选和 Ctrl+单击定位都可以继续查看灰字，随后按 Tab 仍采纳到原来的位置。
- 预览圈和底部时间轴都用普通音符的原色皮肤显示候选。预览圈的候选不透明度为 45%，底部时间轴为 60%，采纳后恢复普通音符的不透明度。候选与正式音符使用相同的音效。流式期间只播放已生成的音符，替换区之外的原谱保留原来的时间。
- 整曲草稿随解码逐拍更新编辑器和预览，并间隔保存当前难度，结束或取消时保存已生成的部分。续写和骨架填充候选在采纳时写入。

## 设备、缓存与采样

Windows x64 设置中的「运行环境下载源」默认优先使用清华 TUNA 下载 pip 依赖，也可选择中国科大、阿里云或仅官方源。国内配置从华为云 NuGet 镜像获取独立 Python，从南京大学、阿里云和上海交大的 PyTorch 专用镜像获取 torch 和 torchaudio。下载失败会自动尝试备用地址，最后回退到官方源。MERT2 使用 Hugging Face 官方仓库。切换下载源只影响后续安装。

谱面模型和 MERT 可分别选择 CPU 或 CUDA。谱面 CPU 默认使用 4 个线程。完整包带有 `app/noa-copilot/env/python.exe`，轻量包可在高级设置中扫描或指定本地 Python。CUDA 支持 Windows 与 WSL Python，两个设备设置共用所选 CUDA 路径。使用两个不同环境时，MERT 只在提取时启动，提取完成后退出。同进程 CUDA 提取完成即释放 MERT 权重和空闲显存，CPU 提取可在切歌时复用权重。设置中的“浏览…”可分别选择解释器。环境扫描分别判断谱面解码与 MERT 能力，MERT 模型需要 torchaudio 的频谱变换。

Windows x64 轻量包支持在 NoaCopilot 设置中按需安装 PyTorch 2.11.0 CPU 或 CUDA 12.6 版。应用把独立 Python 和音频依赖安装到 `app/noa-copilot/environments`，安装完成后选择该解释器。高级设置按 CPU、CUDA 分别列出缺失的包和 DLL。再次点击对应的安装按钮会修复应用内置环境，复查通过后显示就绪。CUDA 版也支持 CPU 推理；尚无可用 CPU 环境时，两项共用新装的 CUDA 版。

项目缓存位于音频旁的 `.miacode/.noacopilot/`。MERT、RoFormer 和 Drafter 特征自动保存。高级设置显示已索引项目和旧版 NoaCopilot 公共缓存的合计占用。“清理全部缓存”按文件报告成功和失败数，已移走的文件直接跳过。首次有 BPM 或拍速图、偏移、难度条件发生变化时，编辑器会在约半秒后预热。普通音符编辑复用现有网格，修改定数只更新条件特征。音频结束之后的手写长音仍能延续。同曲替换音频按内容重新绑定缓存。

“slide出现概率”默认 1.0x，最高 4.0x。在可采样动作中，三类合法 Slide 星头的总概率乘以所选倍率，上限为 100%。例如 20% 在 2.0x 时变为 40%。星头之间和其余动作之间分别保留原有相对比例。随机种子默认 `-1`，每次请求重新取种。非负整数可在同一环境、权重及输入下复现采样。所有温度共用同一棵候选树。每一步按温度 1 和设置的 Slide 倍率确定分支，最可能的动作达到 0.98 时锁定，其他步骤保留首选和概率至少为 0.03 的次选。温度影响探索顺序，同一锚点下按实际音符去重。

## 重建推理包

1. 使用 Qt 6.11.1 的 Release 目录构建 `MiaCode` 和 `MiaCodeLauncher`。运行 `scripts/build/package-win.ps1` 打包到新的发布目录，加 `-NoTorch` 可生成使用外部 Python 的轻量包。默认使用本仓库的 `resources/noa-copilot/runtime-src` 和对应的 `runtime.json`。更新已安装的推理源码时，关闭编辑器，将这两项覆盖到安装目录的 `app/noa-copilot/`，然后重新启动。可用 `MIACODE_FLAT_SOURCE` 和 `MIACODE_NOA_PYTHON_ENV` 指定源码仓库和可搬移的 Windows Python 环境。

2. 两种发布包都省略 MERT2 权重。用户从 NoaCopilot 设置点击「下载 MERT2」后，应用用选定的音频特征推理环境下载官方 FullSong 快照并裁剪到前八层。安装目录包含原许可证、来源和裁剪说明，安装成功后清理下载的完整快照。已有八层模型的离线安装可继续使用。

3. 通过 `MIACODE_WSL_DISTRO` 和 `MIACODE_WSL_PYTHON` 指定本包的初始 CUDA 环境。本机使用 `Ubuntu-22.04` 的 `/home/dev/.venvs/sheetsage2-cu126/bin/python`。内置模式升级时会替换上一发布包写入的默认解释器，用户选择的其他解释器继续生效。两种设备均从 `app/noa-copilot/models/mert-v2` 加载本地前端。
